# Review of c626050

Verdict: **FIX-FIRST**

No HIGH findings. Two MED regressions affect the first-use experience; one LOW sizing defect needs cleanup.

1. **MED — The desktop guide obscures the word being entered.** `src/app.css:136`, `src/app.css:144`. The narrow vertical deck puts the word field directly above the plunger, but `src/guide.tsx:41` still requests an above-plunger tip. Typing the first character advances the guide while the user is still entering their word. At 1100×900 the 250px-wide tip covers the entire 185px-wide input, hiding subsequent typing and intercepting pointer attempts to edit it. At 1440×900 it covers the text and almost the entire field. The parent already had partial overlap, but its wider field extended beside the tip; this layout makes the obstruction worse. Give the desktop tip a placement outside the deck, with collision checks against the input and other controls. Verify typing, correcting the word, and submitting with the guide open.

2. **MED — Desktop placard copy pushes the mobile primary action below the fold.** `src/App.tsx:204`. The new metadata paragraph renders at every width even though this change is meant to preserve mobile. On a fresh touch-emulated 390×844 viewport, the parent plunger occupies y=766–824 and is fully visible; this commit puts it at y=812–870. The hero grows from about 58px to 104px, accounting for that displacement. Users must now scroll to see the complete primary action, and document height grows from 1060px to 1106px. Restrict the new placard copy to the desktop breakpoint. The unconditional `.deck-pair` also changes mobile control order from take/share/sound to take/sound/share; preserve the previous arrangement if mobile preservation is a requirement.

3. **LOW — Flex shrinking clips the fixed-width machine grid.** `src/app.css:114`, `src/app.css:115`, `src/app.css:119`, `src/app.css:170`. `.machine` retains the default `flex-shrink: 1`, but its two grid columns cannot shrink. The width formula reserves 620px without accounting accurately for the placard, responsive gap, page padding, and borders. At 1024×768 the machine is about 620px wide while its columns need 622px plus borders. At 1240×1000 it is about 829px wide while the columns need 838px plus borders. `overflow: hidden` silently crops the rail and right deck edge instead of resolving the mismatch. Default controls remain usable, but right padding and fittings become asymmetric. Prevent machine shrinking and budget the available width explicitly, allowing the placard to shrink with `min-width: 0`, or derive the board width from the actual remaining space. Check child bounds, not just document overflow.
